# Восстановление exclusive-пула на клиентском трафике

Фоновый процесс LiteLLM обновляет каталог и освобождает просроченные операции в Redis. После cooldown Redis допускает один подходящий клиентский запрос без серверных ссылок на физический апстрим. Успешное завершение запроса возвращает все его модели в ready. При локальном 429 Dario с маркером `pool_parked` LiteLLM один раз выбирает другой физический апстрим в рамках того же клиентского запроса. Это применяется до начала ответа клиенту и только к запросам, которые не используют и не создают серверную привязку. При отсутствии кандидата клиент получает исходный 429

Для уже работающего мониторинга Farm предусмотрен экспорт последней записи по каждому инстансу. На стороне Farm запустить `python3 scripts/export_dario_pool_health.py /var/lib/dario-farm/bot.db`. Скрипт читает SQLite в режиме read-only и выдаёт JSON. Передавать его на stdin команды `docker compose run --rm -T --no-deps pool-admin dario-health` на стороне пула по существующему административному каналу. Чтобы использовать интервал опроса Farm в минуту, доставлять снимки раз в минуту. Время наблюдения берётся из Farm и сравнивается с часами Redis, поэтому часы обеих машин должны быть синхронизированы

Статусы `unavailable` и `rate_limited` исключают апстрим из маршрутизации на три минуты с момента наблюдения либо до известного `retry_at` для лимита. LiteLLM также учитывает `Retry-After` в клиентском 429. В Dario 6.25 обычный `/health` читает локальное состояние, а `/health?probe=1` запускает inference. `/v1/models` может вернуть встроенный каталог при сбое запроса к провайдеру

Успешный OAuth refresh и явный `account_on_hold` принимаются как отдельные наблюдения с физическим ID в поле `upstream` и Unix-временем события в секундах в `observed_at`. Экспорт из SQLite передаёт только данные health. Подтверждения refresh и hold должен передавать источник событий Dario. Для refresh использовать фактическое время обновления токена. `refreshGrant` описывает возраст исходного grant. При подтверждённом hold все модели апстрима остаются disabled. После устранения причины оператор допускает следующую клиентскую попытку через `pool-admin enable --resource <deployment-id>`

## Доставка снимков в прод

На `dario-farm-control` установить экспортёр из того же релиза, что и LiteLLM. Запускать экспорт по systemd timer раз в минуту. Учётной записи экспортёра нужен доступ на чтение базы Farm. Вывод экспортёра передавать на `pool.fan-fuel.com` по SSH. На стороне пула выделить ключ с фиксированной командой, которая идёт в каталог Compose и передаёт stdin в `pool-admin`. У ключа отключить интерактивный вход и перенаправление портов. Административный API LiteLLM и Redis для этой доставки остаются во внутренней сети

После настройки выполнить один прогон:

```bash
set -euo pipefail
python3 /opt/dario-farm/export_dario_pool_health.py /var/lib/dario-farm/bot.db |
  ssh -T -o BatchMode=yes -o ConnectTimeout=5 litellm-farm-health
```

На приёмнике фиксированная команда:

```bash
cd /root/litellm/docker/exclusive-pool
exec docker compose run --rm -T --no-deps pool-admin dario-health
```

На сервере пула проверить, что `dario_health[].observed_at` обновляется для известных `upstream` и что свежий `rate_limited` исключает апстрим из доступных. Настроить алерт на отсутствие успешной доставки дольше трёх минут. После потери доставки маршрутизация опирается на уже известные паузы и реальные клиентские ответы. Экспорт снимков SQLite не поставляет события OAuth. Для них отправить отдельный JSON с тем же форматом из источника, различающего подтверждённое обновление токена и `account_on_hold`
